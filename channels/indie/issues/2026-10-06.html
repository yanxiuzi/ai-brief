GitHub 发布 ReviewBench：AI 代码评审的公开基准

GitHub 上线 ReviewBench，一个针对代码评审 agent 的离线基准，基于真实 GitHub PR 构建，并参照 GitHub 上超过 1 亿个真实 PR 的语言、仓库规模和规模分布；采用多来源 golden set 与统一评分标准，并由资深工程师独立验证。GitHub 称 Copilot code review 用它做离线评估后，更能预测生产实验的方向。

对你的价值：如果你在给产品加 AI 评审，或把「AI 帮你看 PR」当卖点，先弄清不同评审器的取舍：有的报得多但噪音大，有的只抓关键问题。这个基准提供按严重程度、类别、precision-recall 拆分的口径，比拿几个玩具仓库自测靠谱。注意它是 GitHub 自家做的，评估口径自己再复核一遍。

踩坑与风险

三个垃圾邮件投诉，你的 SaaS 邮件就进垃圾箱

oliviapp.com 的文章《Three spam complaints and your SaaS is in the spam folder》给出一个具体阈值：少量投诉就可能让你的邮件被判为垃圾邮件。同期 Lobsters 上有自托管邮件的人抱怨，iOS 原生邮件客户端收信极慢，已经影响到接收 OTP 邮件。

对你的价值：注册验证、找回密码、付款回执都直接决定付费转化，一旦进垃圾箱，用户不会找你要重发，只会走人。检查两件事：发信域名有没有独立子域与认证（SPF/DKIM/DMARC），以及是否有人能轻易点「举报垃圾邮件」（比如给不活跃用户群发营销信）。

今天就能做

  • 做一次「模型自检」：向主流模型提问你的品类（例如「推荐一个做 X 的工具」），记录它给出的产品与理由，检查自己官网与定价页信息是否最新；若模型引用的是停更或过期信息，立刻更新页面。
  • 检查邮件送达链路：事务邮件走独立子域，SPF／DKIM／DMARC 配置齐全，营销邮件与验证信分开，避免一次性群发把注册验证和付款回执拉进垃圾箱。
  • 给 AI 功能加一行成本日志：记录每次 agent run 的 token／调用次数并关联订单号，先跑一周看毛利；同时留意 AUDR 这类「agent 运行成本」开放标准的进展，别按用量定价却算不清成本。
